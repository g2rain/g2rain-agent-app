# v1.0.0 · g2rain-agent-app 首个稳定版

G2rain（谷雨）是面向企业的开源智能体平台，连接模型、知识与业务工具，并以 SaaS 基座和应用开发工具链支撑智能应用落地。组件是否已发布、接入范围和验证状态以各责任仓库为准。`g2rain-agent-app` 是平台中的 Vue 3 数字员工控制台微前端业务应用，提供 Agent、模型服务、MCP 工具、对话与任务追踪等页面的前端交互、资源路由与 qiankun 生命周期适配；实际模型调用、智能体执行、认证、网关和数据安全由对应后端组件与部署环境负责，不能将平台整体能力归因于本组件。

## 构建、运行与镜像

- 项目版本事实源：根目录 `package.json`（`1.0.0`）；`package-lock.json` 根包与 `docs/project.yaml` 已同步为 `1.0.0`。许可证为根目录 [Apache License 2.0](../../LICENSE)，镜像标签为 `Apache-2.0`。
- 构建要求：Node.js `>=22` 与 npm；`npm ci` 按 lockfile 安装，`npm run build` 执行 `vue-tsc` 与 Vite 构建。本仓没有独立 `npm test`、lint 或 E2E 脚本。
- 容器复用根目录 `Dockerfile` 与 `build.sh`：Node 22 Alpine 构建静态文件，OpenResty Alpine 运行，入口为 `/docker-entrypoint.sh`，声明端口 `8080`；实际监听端口由 `SERVER_PORT` 决定，默认值是 `80`。
- 镜像为 `ghcr.io/g2rain/g2rain-agent-app:1.0.0` 及 `ghcr.io/g2rain/g2rain-agent-app:sha-<完整提交 SHA>`；不发布或更新 `latest`。OCI 元数据包含 title、source、url、version、revision 与 `Apache-2.0` 许可证。
- 最终镜像包含 Vite `dist`、Lua 签名代码、Lua 配置、Nginx 模板和入口脚本；不包含源码、`package-lock.json`、`.env*` 或 `lua/keys/`。`SSO_BASE_URL` 是唯一由当前入口写入 `env-config.js` 的运行时前端变量。

## 发布顺序与 GHCR

1. 按 `feature/* → develop → main` 将版本、工作流和本说明合入 `main`，在该提交完成验证。
2. 在已验证的 main 提交创建并推送 `v1.0.0`。工作流只接受精确 `v<major>.<minor>.<patch>` 格式，验证 tag 提交在 `main` 历史、同名发布说明非空且 tag 与 `package.json` 版本一致。
3. GitHub Actions 使用 `GITHUB_TOKEN`，仅有 `contents: read` 与 `packages: write`，执行 `npm ci`、`npm run build`、镜像构建并依次推送两个标签。Actions Summary 仅在两个标签均成功推送后记录完整镜像地址；工作流不创建 GitHub Release、不部署服务、不更新 `latest`。
4. 首次成功推送后，如需匿名拉取，在 GitHub **Packages → g2rain-agent-app → Package settings → Change visibility → Public** 将包设为 Public；若组织管理员禁止修改，请联系管理员。已有包遇到 GHCR `denied` 时，先检查 **Package settings → Actions access** 是否向 `g2rain/g2rain-agent-app` 授予写权限，再检查组织 Packages 策略；`packages: write` 本身不足以保证权限。

公开后可匿名拉取：`docker pull ghcr.io/g2rain/g2rain-agent-app:1.0.0`。私有包需要以具备 `read:packages` 权限的凭据登录。

## 配置、安全与验证范围

生产环境以 Secret 或只读 Volume 挂载 `/usr/local/openresty/nginx/lua/keys`，提供 Lua 私钥、公开密钥、IAM 公钥和可选 Key ID；不得经 `VITE_*`、镜像、命令行或仓库提交传递生产密钥。虽然本镜像已排除 `lua/keys/`，仓库仍跟踪 `lua/keys/private-key.pem` 和 `lua/keys/private-key.der`；维护者必须在公开前确认它们仅为可公开样例，若曾被任何环境使用则须移除/替换并轮换。Docker 忽略规则不会消除 Git 历史或源码公开风险。

本次发布准备不声称已经完成本地构建、容器构建、GHCR 推送、匿名拉取、在线演示或实际部署验收。CI 的自动验证范围仅为 `npm ci`、Vue/TypeScript 类型检查和 Vite 打包；它不证明容器启动、Nginx/Lua 路径、运行时密钥注入、Gateway/IAM/SSO 联调、qiankun 集成、浏览器 E2E 或生产部署。实际发布结果以 Actions 记录和目标环境验收为准。
