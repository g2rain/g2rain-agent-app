## 1. 背景

`g2rain-agent-app` 的页面由生成器按表生成，每张表一个 CRUD 页：绑定表、运行明细表各自成页，枚举、长文本、JSON 字段都用单行输入框，接口路径缺少网关前缀，运行观测表还暴露了新增与删除。运营方和租户看到的是同一套表，无法体现「公共资源 + 私有资源」的使用方式，也看不出一次任务是怎么执行的。

## 2. 目标

- 按业务对象重组为 4 组菜单（模型、工具、智能体中心、会话管理）、7 个菜单页（另有三期的概览）、3 个嵌入页（见第 6 节）。
- 模型、工具、智能体三类配置区分公共与私有：运营方维护公共资源，租户引用公共资源并维护私有资源。
- 运行观测按「会话列表 → 会话详情 → 执行追踪」逐层下钻；执行追踪以有向无环图展示任务，点击节点查看执行轨迹与工具调用。
- 技能在智能体配置中管理，不单独设菜单。
- Markdown、JSON 字段使用专用编辑器；技能契约可按工具逐个查看并实时校验。
- 所有用户可见文案国际化，页面跟随所选语言。

## 3. 非目标

- 不修改 chat-shell、main-shell 的菜单与 Tab 机制。
- 不实现后端能力；依赖的后端接口在第 9 节登记，由后端排期。
- 不做用户级数据隔离（当前只有租户级）。
- 不提供运行数据的修改、删除、重试或取消。
- 不提供跨会话的任务、工具调用排查列表；需要时再在会话管理下增加「运行排查」菜单，结果同样跳转执行追踪。

## 4. 角色与可见性

运营方通过 `basis.organ.admin = 1` 识别（前端如何获知见[指导文档待确认事项](../design/agent-console.md#12-待确认事项)）。运营方本身也是一个机构，可以像租户一样配置自己的私有资源。

| 资源 | 运营方 | 租户 |
|---|---|---|
| 模型目录（菜单） | 独立维护 MARKET；查看全部 CUSTOM | 不可见 |
| 广场模型 MARKET | 增删改 | 在模型配置中选择引用（只读，不返回 `api_key`） |
| 私有模型 CUSTOM | 本机构通过模型配置维护 | 在模型配置中随配置一起增删改 |
| 模型配置 | 本机构增删改 | 本机构增删改 |
| 用量 | 本机构（全平台视图为二期） | 本机构 |
| 外部服务 EXTENSION | 增删改、导入 OpenAPI | 不可见 |
| 外部服务 CUSTOMER | 本机构增删改 | 本机构增删改 |
| 工具 BUILT_IN / EXTENSION | 同步、启停、改说明 | 只读 |
| 工具 CUSTOMER | 本机构增删改 | 本机构增删改 |
| 智能体 / 技能 PLATFORM | 增删改 | 只读；可绑定 PLATFORM 技能；可「复制为私有」（需后端） |
| 智能体 / 技能 CUSTOM | 本机构增删改 | 本机构增删改；技能在智能体配置中维护 |
| runtime 全部表 | 本机构只读 | 本机构只读 |

前端规则：

- 公共资源行显示来源徽标（广场 / 平台 / 内置 / 扩展），租户侧隐藏编辑、删除，只保留「查看」。
- 按钮权限仍用静态 `v-permission`；运营方专属按钮（同步、导入、维护广场）用独立权限点，由 IAM 只授予运营方角色，不在前端硬编码 `admin` 判断。
- 新增时 `resource_type` 由页面决定，不让用户选：租户新增一律 CUSTOM / CUSTOMER；运营方在「模型目录」「平台工具」页新增才是 MARKET / EXTENSION / PLATFORM。

## 5. 菜单

一级为分组，二级为菜单入口页。linkPath 用简短业务名，替换现在的表名路径。

```text
智能体控制台
├── 概览              /overview          (三期)
├── 模型
│   ├── 模型目录      /model_catalog     (仅运营方)
│   ├── 模型配置      /model_profile
│   └── 用量统计      /model_usage
├── 工具
│   ├── 服务接入      /mcp_service
│   └── 工具目录      /mcp_tool
├── 智能体中心
│   ├── 智能体列表    /agent
│   │   ├── [配置]   → 智能体配置 /agent_config?agentId=             嵌入页
│   │   └── [技能 N] → 智能体配置 /agent_config?agentId=&tab=skill   嵌入页
│   │                    └── 技能行 [配置] → 技能配置                抽屉
│   └── 智能体模板    （规划中，本期不做）
└── 会话管理
    └── 会话列表      /conversation
        └── 会话详情  /conversation_detail?conversationId=            嵌入页
            └── 执行追踪  /task_trace?taskId=                          嵌入页
                  任务图（DAG）+ 节点详情（含工具调用）
```

| 菜单页 | 主表 | 运营方 | 租户 | 说明 |
|---|---|---|---|---|
| 模型目录 | catalog | 维护 MARKET，查看 CUSTOM | 不可见 | 目录页，菜单只授权给运营方 |
| 模型配置 | profile（+ CUSTOM catalog） | 本机构 | 本机构 | 从广场选模型或接入私有模型，再配参数 |
| 用量统计 | usage_record | 本机构 | 本机构 | 时间范围、按模型聚合 |
| 服务接入 | external_service | EXTENSION + 本机构 CUSTOMER | 本机构 CUSTOMER | 导入 OpenAPI 入口 |
| 工具目录 | tool_profile | 全部来源 | 公共只读 + 本机构 CUSTOMER | 按来源分 Tab |
| 智能体列表 | agent_profile | PLATFORM + 本机构 | 公共只读 + 本机构 | 卡片「配置」「技能 N」→ 智能体配置 |
| 会话列表 | chat_conversation | 本机构 | 本机构 | 下钻：会话详情 → 执行追踪 |

原有的 `task_graph_node`、`task_graph_edge`、`task_node_payload`、`task_checkpoint`、`task_resume_record`、`chat_message`、`agent_skill_binding`、`skill_tool_binding` 页面**下线菜单**，能力并入嵌入页。是否保留为运维兜底页见[指导文档待确认事项](../design/agent-console.md#12-待确认事项)。

## 7. 页面需求

接口路径已包含网关前缀：模型 `/model`、智能体 `/studio`、运行 `/harness`；MCP 暂按 `/mcp`，以最终确认为准。备注为「待后端」的接口当前不存在，页面对应功能按开发分期后置。

### 7.1 P01 模型目录

| 项 | 内容 |
|---|---|
| linkPath | `/model_catalog` |
| 页面模板 | 目录页 |
| 可见角色 | 运营方 |
| 权限点 | `model_catalog:add` `model_catalog:edit` `model_catalog:delete` |

**功能**

- 「广场 / 私有」分段切换；按类型、供应商、关键字筛选
- 新增、编辑、停用、删除广场模型（MARKET）；被引用时禁止删除
- 连接测试（协议、地址、密钥是否可用）
- 只读查看各租户接入的私有模型（CUSTOM）及所属机构

**接口**

| 方法 | 路径 | 用途 | 备注 |
|---|---|---|---|
| GET | `/model/model_service_catalog/page` | 分页查询（resourceType、modelType、provider、status、modelName） | — |
| POST | `/model/model_service_catalog/save` | 新增 / 更新广场模型 | — |
| DELETE | `/model/model_service_catalog/{id}` | 删除广场模型 | — |
| POST | `/model/v1/chat/completions` / `embeddings` / `rerank` | 连接测试 | 请求中 `model` 的取值待确认 |
| GET | — | 被引用机构数、私有模型所属机构 | 待后端 |

**布局与交互**

运营方单独维护的共享目录。菜单和权限点只授权给运营方角色，租户看不到这个页面。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 模型目录  广场模型供所有租户引用；私有模型由租户在模型配置中接入     │
│ [广场 | 私有]  [全部类型 | 大语言 | 向量 | 重排序]  [搜索] [供应商▾] │
│                                                        [新增广场模型]│
├──────────────────────────────────────────────────────────────────────┤
│ ┌────────────────────┐ ┌────────────────────┐ ┌────────────────────┐ │
│ │ 千 Qwen3.6-27B-bw  │ │ 千 Qwen3-Embedding │ │ 千 Qwen3.8-27B     │ │
│ │ 千问 · OPENAI    ⋯ │ │ 千问 · OPENAI    ⋯ │ │ 千问 · OPENAI    ⋯ │ │
│ │ [大语言]   ● 启用  │ │ [向量]     ● 启用  │ │ [重排序]   ● 启用  │ │
│ │ 千问自建大语言模型 │ │ 千问自建向量模型   │ │ 千问重排序模型     │ │
│ │ 被 3 个机构引用    │ │ 被 1 个机构引用    │ │ 未被引用           │ │
│ └────────────────────┘ └────────────────────┘ └────────────────────┘ │
└──────────────────────────────────────────────────────────────────────┘
```

- **广场**分段：卡片网格（宽 320px，自适应列数）。卡片显示供应商首字母图标、模型名、供应商与协议、类型、状态、说明、被引用机构数。`⋯` 菜单：编辑、停用、删除；有引用时删除置灰并提示先停用。
- **私有**分段：表格（模型、类型、协议、服务地址、所属机构、状态），只读。用于运营方排查租户接入的模型；所属机构经 profile 关联得出。
- 抽屉表单（560px）分两组：**模型**（调用标识、类型、供应商、说明）与**连接**（协议、服务地址、访问密钥 `SecretInput`），底部有「测试连接」。`resourceType` 由所在分段决定，固定为 MARKET。

**验收**

- [ ] 租户账号看不到菜单，直接访问 linkPath 返回无权限
- [ ] 广场模型被配置引用时，删除按钮置灰并提示先停用
- [ ] 访问密钥只在表单中以掩码出现

### 7.2 P02 模型配置

| 项 | 内容 |
|---|---|
| linkPath | `/model_profile` |
| 页面模板 | 列表页 |
| 可见角色 | 运营方、租户 |
| 权限点 | `model_profile:add` `model_profile:edit` `model_profile:delete` `model_profile:test` |

**功能**

- 配置列表：按类型、来源、状态、关键字筛选；行内启停
- 新增 · 从广场选择：选一个 ACTIVE 广场模型 + 配置参数，只创建 profile
- 新增 · 接入私有模型：填写模型与连接信息 + 配置参数，同时创建 CUSTOM 目录与 profile
- 编辑：广场来源只改参数；私有来源可改目录字段与参数
- 删除：私有来源连同其 CUSTOM 目录一起删除
- 试一试：用该配置发起一次调用并显示结果与耗时

**接口**

| 方法 | 路径 | 用途 | 备注 |
|---|---|---|---|
| GET | `/model/model_service_profile/page` | 分页查询，返回 `ModelServiceDetailVO`（已联表目录字段） | — |
| GET | `/model/model_service_catalog/list` | 广场模型候选（resourceType=MARKET、status=ACTIVE） | 租户侧需后端收口，不返回 `api_key` |
| POST | `/model/model_service_profile/save` | 从广场选择：创建 / 更新 profile | — |
| POST | `/model/model_service_profile/save` | 接入私有模型：携带 catalog 字段，同事务写入目录与配置 | 待后端 |
| DELETE | `/model/model_service_profile/{id}` | 删除配置（私有来源级联删除目录） | 级联删除待后端 |
| POST | `/model/v1/chat/completions` / `embeddings` / `rerank` | 试一试 | — |

**布局与交互**

租户（以及作为普通机构的运营方）管理模型的唯一入口。一条配置就是「一个可用的模型」。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 模型配置  配置后即可在智能体和对话中使用                [新增模型 ▾]│
│ [全部 | 大语言 | 向量 | 重排序]  [搜索]  [来源▾] [状态▾]  ├ 从广场选择│
├───────────────────────────────────────────────────────────└ 接入私有模型
│ 模型                    来源    类型    参数                超时  状态│
│ Qwen3.6-27B-bw          [广场]  大语言  T 0.00 · P 1.00 ·  120 s  ●  │
│ 千问 · OPENAI                           4096 tokens                  │
│ my-deepseek-v3          [私有]  大语言  T 0.70 · P 0.95 ·   60 s  ●  │
│ DeepSeek · OPENAI                       8192 tokens                  │
└──────────────────────────────────────────────────────────────────────┘
```

表格列：模型（名称 + 供应商与协议）、来源（徽标：广场 / 私有）、类型、参数摘要、超时、状态（行内开关）。数据来自 `GET /model/model_service_profile/page`，返回的 `ModelServiceDetailVO` 已联表带出目录字段。

**新增有两条路径**，都在 720px 抽屉中完成：

```text
从广场选择                                     接入私有模型
┌────────────────────────────────────┐         ┌────────────────────────────────────┐
│ ① 选择模型                          │         │ 模型                               │
│ [大语言|向量|重排序]  [搜索]         │         │ 调用标识 [my-deepseek-v3        ]  │
│ ○ Qwen3.6-27B-bw   千问 · 大语言    │         │ 类型 [大语言▾]  供应商 [DeepSeek]  │
│ ○ Qwen3-Embedding  千问 · 向量      │         │ 连接                               │
│ ✓ 已配置项置灰                      │         │ 协议 [OPENAI▾]                     │
│ ② 参数                              │         │ 服务地址 [https://…            ]   │
│ temperature ━━●━━━━  0.00          │         │ 访问密钥 [••••••••••]  [测试连接]  │
│ top_p       ━━━━━━●  1.00          │         │ 参数                               │
│ 最大输出    [4096]                  │         │ （与左侧「② 参数」相同）           │
│ 超时        [120] 秒                │         │                                    │
│                    [取消] [保存]    │         │                    [取消] [保存]   │
└────────────────────────────────────┘         └────────────────────────────────────┘
```

- **从广场选择**：上半部分是可搜索的广场模型单选列表（只返回 MARKET 且 ACTIVE；已配置的置灰并标「已配置」），下半部分是参数。保存时只创建 profile（关联 + 属性）。
- **接入私有模型**：上半部分填写目录字段，下半部分是参数。保存时**一次请求**同时创建 CUSTOM 目录与 profile，见[指导文档第 9 节](../design/agent-console.md#9-后端缺口)。
- 参数组：大语言显示 temperature（滑块 + 数字，0–2，步长 0.05）、top_p（0–1）、最大输出 tokens；向量、重排序隐藏这一组。超时按秒输入，提交时换算成毫秒。
- **编辑**：广场来源只能改参数，目录信息只读展示；私有来源可同时改目录字段和参数，访问密钥留空表示不修改。
- **删除**：广场来源只删除配置；私有来源同时删除对应的 CUSTOM 目录，确认框里说明这一点。
- 详情抽屉右侧有「试一试」：大语言发一句短消息，向量输入一段文本，重排序输入查询和两段候选文本，显示结果与耗时。

**验收**

- [ ] 同一页面完成两条新增路径，不跳转其他菜单
- [ ] 已配置的广场模型在选择列表中置灰
- [ ] 向量、重排序模型不显示采样参数
- [ ] 超时按秒输入，提交为毫秒

| linkPath | `/model_usage` |

**上区 · 任务图**

- 用 `@vue-flow/core` 渲染，`@dagrejs/dagre` 自动布局，方向从左到右。图区高度按节点数自适应（240–420px），与下区之间有可拖动的分隔条，位置按用户记忆（`localStorage`，读写包在 try/catch 里）。
- 两端各加一个虚拟节点：**用户请求**（`task_instance.request`、开始时间）和**结果**（终态、`final_message`）。没有前驱的节点连到「用户请求」，没有后继的节点连到「结果」，让图有明确的起点和终点。
- 业务节点卡片（宽 220px）：

  ```text
  ┌──────────────────────┐
  │ ● 保存文章        [写]│   状态点 + 标题（最多两行）+ 写标记

  │ 8 s · 1 次调用        │   耗时 · 调用次数

  └──────────────────────┘
  ```

  - 失败节点左侧显示红色竖条；进行中的节点状态点呼吸闪烁；SKIPPED、CANCELLED 节点整体淡化。

- 边：NORMAL 为实线箭头；DELEGATE 为虚线并标「委派」。被其他路径覆盖的冗余依赖（样例任务 `9b1c31bd` 中的 ① → ③）默认淡化，工具栏可切换「只看直接依赖」。
- 工具栏：适应画布、缩小、放大、全屏。节点不可拖动、不可连线，只读。
- 节点多于 12 个时显示小地图；样例中最大的任务只有 3 个节点，默认不显示。

**下区 · 详情**

点击不同对象，下区展示不同内容；默认选中「结果」节点（失败任务默认选中第一个失败节点），点击画布空白处回到任务详情。

| 选中对象 | 详情页头 | Tab |
|---|---|---|
| 用户请求 | 开始时间、来源消息 | **请求**：用户原文；**前情**：`prior.tasks` 列表（目标、状态、摘要）；**共享值**：`shared`（`JsonViewer`） |
| 业务节点 | 标题、状态、技能键、完成目标、轮次、耗时 | 见下表 |
| 结果 / 画布空白 | 终态、总耗时 | **任务**：目标、智能体、起止时间、`final_message`；**产生的对象**：`record.entities` 卡片；**确认记录**：检查点问题文案与恢复动作时间线；**消息**：本任务关联的对话消息 |

业务节点的 Tab：

| Tab | 内容 | 数据 |
|---|---|---|
| 概要 | 目标（objective）、完成目标工具、结论（result，`MarkdownViewer`）、错误码与错误信息、依赖步骤、起止时间 | `task_graph_node` |
| 执行轨迹 | 按轮次排列的动作时间线（见下） | `node.state.actions` + `tool_call_record` + `task_resume_record` |
| 工具调用 | 本节点的业务调用表：轮次、工具、结果、耗时；展开行显示请求、响应、实体；有 `payload_id` 时按需加载大报文 | `tool_call_record` + `task_node_payload` |
| 便签 | 节点便签（`node.state.state`）键值列表，值用 `JsonViewer` | `task_graph_node.state` |
| 输入输出 | `inputs`、`outputs`，以及每个值的来源 | `task_graph_node` |
| 消息 | 节点中间文字（有 `node_id` 的消息），没有时隐藏该 Tab | `chat_message?taskId=&nodeId=` |

Tab 标题带数量（`工具调用 1`）；切换节点时保持当前 Tab，便于横向比较。

**执行轨迹**是排查问题最直接的视图：

- 每一轮一行：轮次号、执行者图标（智能体 / 用户）、动作名、一句话结果。内置工具用中文动作名（`builtin_node_approval` → 申请确认，`builtin_node_finish` → 完成节点，`builtin_state_set` → 写入便签，`builtin_node_fail` → 节点失败，`builtin_node_follow_up` → 追问用户，`builtin_session_info` → 会话信息）；业务工具显示工具名和「写」标记，点击跳到「工具调用」Tab 的对应行；行上「详情」打开 720px 工具调用详情抽屉（概要 / 请求 / 响应 / 实体）。
- runtime 拒绝或拦截的动作（例如「须先成功调用……后再 finish」）用红色文字标出。
- 连续重复的相同动作折叠成一行「相同调用重复 N 次」，可展开。样例失败任务 `61fe525b` 的第 ② 步 9 轮中有 5 轮是同一个被拒绝的完成动作，折叠后一眼就能看出卡死原因。
- 没有真实发出的调用（例如「已复用历史写证据」，耗时 0、`business_ok` 为空）标记为「复用」。

**数据加载**：进入页面并行请求任务、节点、边、检查点、恢复记录，画出图后再按选中节点懒加载工具调用、消息和大报文。

**刷新**：任务处于进行中或等待用户时，页头显示「自动刷新」开关（默认关闭，间隔 5 秒）；任务进入终态后自动停止。刷新时保持当前选中节点和画布视口。

**验收**

- [ ] 节点「写」「已确认」标记按调用实际发生的节点显示
- [ ] 两个 Tab 同时打开不同任务互不影响
- [ ] 任务进入终态后自动刷新停止
- [ ] 面包屑「会话列表 / 会话详情 / 执行追踪」；从 chat-shell 直开时只显示「执行追踪」

## 13. 发布与回滚

- 按[开发分期](../design/agent-console.md#11-开发分期)分批发布，每期独立提测。
